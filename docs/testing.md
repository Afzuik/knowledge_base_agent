### 真实链路样例

对公开原创资料 budget-a.md / budget-b.md 分别建立实际 Chroma 索引：

- 只选 A：回答 120 元人民币，引用仅来自 A。
- 只选 B：回答 350 元人民币，引用仅来自 B。
- 同时选择：分别列出 120 / 350 的冲突，两份资料均有对应引用。
- 问负责人：说明所选资料没有记录，不编造姓名。
- 同来源追问币种：结合历史指代，回答人民币并引用原文。

此前还验证了从 BGE 1024 维索引切换到 Qwen 4096 维：旧索引不兼容、重建后版本改变，不混用向量。

## 最终浏览器验收

使用正式应用、真实模型和独立测试目录，而非模拟响应：

1. 在页面创建“DeepSeek 官方模型最终验收”专题。
2. 通过文件选择器上传 A，点击“建立索引”，等待可检索。
3. 勾选 A、提交问题，观察检索/生成状态和流式回答。
4. 点击引用，核对预算原文、文件名和文本位置。
5. 停止并重新启动实际后端；刷新页面，历史消息和引用仍存在。
6. 勾选 A 继续追问币种，使用持久化向量索引和官方 LLM 正常回答。
7. 再次点击引用，显示对应的原文快照；未观察到浏览器 JavaScript 错误。

独立的 TEST DOUBLE 环境另外验证了流式停止和刷新后的未完成状态；该环境与真实模型结果明确分开，不作为真实模型质量证据。

## 过程中的问题及处理

- 旧 SiliconFlow 配置后续曾返回 HTTP 402；应用正确显示失败，未伪报成功。用户恢复服务后改用指定的新模型重新验收。
- `deepseek-flash` 在 SiliconFlow 返回 400。用户明确要 DeepSeek 官方服务后，拆分服务地址与 Key，最终官方普通/流式调用通过。
- 模型偶尔使用圆括号表示引用，增加有限格式归一化；仍需验证编号属于本轮证据。
- 引用版本改为绑定检索快照，避免重建过程中元数据变化导致版本标识混淆。
