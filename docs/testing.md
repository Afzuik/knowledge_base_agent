### 真实链路样例

对公开原创资料 budget-a.md / budget-b.md 分别建立实际 Chroma 索引：

- 只选 A：回答 120 元人民币，引用仅来自 A。
- 只选 B：回答 350 元人民币，引用仅来自 B。
- 同时选择：分别列出 120 / 350 的冲突，两份资料均有对应引用。
- 问负责人：说明所选资料没有记录，不编造姓名。
- 同来源追问币种：结合历史指代，回答人民币并引用原文。

此前还验证了从 BGE 1024 维索引切换到 Qwen 4096 维：旧索引不兼容、重建后版本改变，不混用向量。

## 研究阶段浏览器验收（历史保留）

使用正式应用、真实模型和独立测试目录，而非模拟响应：

1. 在页面创建“DeepSeek 官方模型最终验收”专题。
2. 通过文件选择器上传 A，点击“建立索引”，等待可检索。
3. 勾选 A、提交问题，观察检索/生成状态和流式回答。
4. 点击引用，核对预算原文、文件名和文本位置。
5. 停止并重新启动实际后端；刷新页面，历史消息和引用仍存在。
6. 勾选 A 继续追问币种，使用持久化向量索引和官方 LLM 正常回答。
7. 再次点击引用，显示对应的原文快照；未观察到浏览器 JavaScript 错误。

独立的 TEST DOUBLE 环境另外验证了流式停止和刷新后的未完成状态；该环境与真实模型结果明确分开，不作为真实模型质量证据。

## 本轮笔记验证

### 自动化

- schema v3 八张业务表；v2 升级保留数据并备份，迁移失败不留下半套新表。
- 仅完整助手回答可保存；来源在当前专题/身份范围内；重复/并发保存复用笔记，编辑不改原回答。
- 引用快照独立，修改原始引用不改变笔记；跨专题读取、编辑、导出被拒绝。
- revision 条件更新，只允许一个并发旧版本写入成功；错误版本和无效编号不导出。
- 存储失败回滚、正文/标题长度、不可写快照字段、Unicode 文件名、下载响应头和动态代码围栏。
- Markdown 中代码/链接里的标记不算引用；HTML 不执行、远程图片不自动加载、不生成危险链接。
- 前端保存请求串行，旧响应不覆盖新输入；失败或冲突保留本地内容。
- 自动保存延迟、导出等待最新保存成功、保存失败不下载、导航拒绝时保留页面与草稿。
- 网络连接被禁止时，笔记完整链路仍可完成；没有新增来源、任务或向量。

### 浏览器与下载文件

在独立副本中使用上轮真实模型生成并持久化的回答，同时禁止模型客户端发起新请求：

1. 保存完整回答为笔记，默认标题来自问题，正文与引用快照保留。
2. 修改标题/正文，自动保存后显示新版本；Markdown 预览显示标题、粗体和列表，引用可点击。
3. 重复保存打开已有笔记，不增加数量、不覆盖编辑。
4. 两个标签页同时编辑，旧版本收到409，冲突输入仍在文本框中，保存/导出被保护。
5. 离开时实际出现确认框；取消导航的具体行为另由前端自动化测试验证，不将未观察的浏览器结果写成通过。
6. 无效引用导致导出按钮禁用。修正后立刻点击导出，先保存再下载。
7. 重新读取浏览器下载的 Markdown，确认最新正文、有效编号、原文快照和中文标题；文件字节与对应 revision 的 API 导出完全一致。
8. 保存第二篇笔记、切换列表；重启实际服务后，两篇笔记及版本4的编辑内容、引用快照均保留。
9. 原 messages/citations/sources/chunks/jobs 逐行比较未变；模型调用禁止标记未触发。

原始记录位于本机被忽略的 `reports/notes/`。导出示例为 `reports/notes/exported-note.md`，不提交测试数据库、下载文件或截图。

## 过程中的问题及处理

- 旧 SiliconFlow 配置后续曾返回 HTTP 402；应用正确显示失败，未伪报成功。用户恢复服务后改用指定的新模型重新验收。
- `deepseek-flash` 在 SiliconFlow 返回 400。用户明确要 DeepSeek 官方服务后，拆分服务地址与 Key，最终官方普通/流式调用通过。
- 模型偶尔使用圆括号表示引用，增加有限格式归一化；仍需验证编号属于本轮证据。
- 引用版本改为绑定检索快照，避免重建过程中元数据变化导致版本标识混淆。
